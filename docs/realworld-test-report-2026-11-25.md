## 六、发现的问题

### 6.1 已修复（4 个）

| 严重度 | 问题 | 实测证据 | 修复 |
|---|---|---|---|
| **P1** | `build` / `out` / `output` 在任意层级命中就被判噪音 | httpie 的 23 个 `.py`（整个 `output/` 包）从未进入统计；修复后 `code 1673→1683`、`empty 17→7`，总数不变 | 歧义目录：仅当文件不是源码扩展名时才丢弃 |
| P2 | 脱敏把所有名为 `key` 的字段当邮箱 | `--anon --json` 的时间轴 key 变成 `dev-xxxx@redacted` | 仅当值含 `@` 时才替换 |
| P2 | 「最深的夜」排序写反 | gin 选中 `01:48`，实际应选 `00:00` | 按时刻取最早 |
| P2 | 单章仓库的「每周提交数」等于提交总数 | 20 次提交跨 10 天，页面显示 20 次/周（实际 14） | `commits / weeks` |

### 6.2 初次判定失败、实为测试写错（2 个）

按上一份报告的做法，这类单独记录 —— 它们说明「测试本身也会骗人」。

1. **未来时间戳没有触发警告**：产品文案写的是「时间戳在将来」，测试却在搜「未来」。改成搜「将来」后通过。
2. **LLM 叙事出现「离谱数字」**：提取逻辑把所有三位以上数字都当成提交数，抓到的 11,518 / 36,148 / 59,600 其实是**行数**。改为只匹配「N 次提交 / N commits」后，5 个章节的声称值（562 / 86 / 1,658 / 678 / 830）全部小于总数 4,197。

### 6.3 样本问题（非产品）

- 两个仓库克隆中断，已从样本移除
- 一个半成品仓库（`book`）留下 HEAD 指向缺失对象的目录，分析时抛 `your current branch appears to be broken` —— 工具按设计保留原始 stderr（未知错误不猜测），CLI 退出码 1。这属于**已知行为**，不是 bug。

真实调用 DeepSeek（模型返回 `deepseek-flash`）：

| 项 | 结果 |
|---|---|
| 耗时 | 4.4 s（冷）/ 6.1 s（二次） |

| 事实一致性 | 声称的提交数 562 / 86 / 1,658 / 678 / 830，均 ≤ 4,197 |

叙事样例（bat）：

> **草创破冰期** — 2018 年 4 月 21 日，sharkdp 写下「Initial commit」，到当年 12 月 24 日已积累 562 次提交、36,313 行新增。目录前三名是 assets、tests、src，测试从第一天起就和源码并列，不是事后补的。
>
> **扩张的减速带** — 2021 年 11 月到 2023 年 8 月，提交数降到 469，周均 4.93，是五章里最慢的；但新增 59,600 行、删除 36,148 行，单次提交的改动量反而变大。

降级路径：

| 场景 | 结果 |
|---|---|
| 401 无效 Key | `used=false`，回落规则叙事，5 章完整，报告可打开 |
| 端口不可达 | 4.8 s 内回落，报告完整（不是卡到 90 s 超时） |
| `--no-ai` | `reason=not_requested`，不尝试连接 |

## 九、已知限制

测出来的行为，不是 bug：

| 限制 | 说明 |
|---|---|
| 章节跨度不均 | 最长章可达 55%（rustlings）。匀速仓库切成三段必然「短-长-短」，长段内部没有突变，硬切会造假阶段 |
| 语言占比 ±0.2pp | 逐项四舍五入的累积误差，合并不足 100% 的情况已由 Other 补齐 |
| 脱敏不脱语义 | anon 报告仍会写「某月大重构、删了 1.6 万行、主战场在 docs」，定位是「发给不认识你的人」 |
| 短于 7 天的历史按 1 周算 | `weeks` 有 1.0 下限，所以 3 天 24 次提交会显示 24 次/周；这是刻意避免除以 0 |
| 真实样本都是 month 粒度 | 11 个仓库历史都超过 130 周；周粒度的行为由构造仓库（10 天）覆盖 |

## 十一、结论

功能面完整，统计口径自洽，边界不崩，脱敏承诺在真实仓库上成立，LLM 失败时报告仍然完整可读。

真正的问题都集中在「输入被悄悄截断」而不是「输出算错」—— 这也是最该警惕的一类：它不会报错，数字彼此自洽，只有反向核对数据源才会暴露。这一轮修掉的 4 个都属于这个类型，并且各自补了回归测试。
